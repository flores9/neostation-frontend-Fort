# R1 Delivery Checklist

A NeoStation Fort release is not final until every required item below is complete.

## Source

- [ ] `fort/esde-integration-r1` is clean and pushed.
- [ ] exact release commit recorded.
- [ ] diff reviewed against upstream base.
- [ ] no signing material or credentials tracked by Git.
- [ ] `main` remains untouched until candidate validation passes.

## Automated/local validation

- [ ] required Flutter version selected from `.fvmrc`.
- [ ] JDK 17 available.
- [ ] `dart format --output=none --set-exit-if-changed lib test` passes.
- [ ] `flutter analyze` passes.
- [ ] `flutter test` passes.
- [ ] Android ARM64 release APK compiles.
- [ ] APK built with permanent Fort signing identity.
- [ ] SHA-256 recorded.

## Device validation

- [ ] complete `R1_TEST_PLAN.md` on the AYN Thor.
- [ ] upstream NeoStation and NeoStation Fort coexist.
- [ ] internal-storage ROM system works.
- [ ] microSD ROM system works.
- [ ] custom ES-DE `MediaDirectory` works.
- [ ] central gamelist works.
- [ ] ROM-local/specific gamelist works.
- [ ] manual ROM override + Reset works.
- [ ] manual media override + Reset works.
- [ ] manual gamelist override + Reset works.
- [ ] removing/revoking microSD access preserves stored games.
- [ ] restoring microSD access recovers cleanly.

## Release artifacts

- [ ] final APK renamed consistently.
- [ ] `BUILD_MANIFEST.txt` included.
- [ ] `SHA256SUMS.txt` included.
- [ ] `GIT_HISTORY.txt` included.
- [ ] `UPSTREAM_BASE_DIFFSTAT.txt` included.
- [ ] Fort docs included.
- [ ] continuity prompt updated to actual final state.
- [ ] completed test plan included.
- [ ] delivery ZIP generated by `fort_local_release.ps1`.

## GitHub publication

Only after all validation passes:

- [ ] choose/freeze Fort version.
- [ ] update source version if required.
- [ ] merge validated branch to fork `main`.
- [ ] create immutable tag from the exact validated commit.
- [ ] create GitHub Release.
- [ ] upload APK.
- [ ] upload delivery ZIP.
- [ ] publish release notes.
- [ ] publish SHA-256.

## Post-release

- [ ] install/update from the uploaded APK once to prove the published binary is the tested artifact.
- [ ] record any deferred items in the continuity prompt / next-release notes.
- [ ] keep upstream sync work separate from Fort feature work.
